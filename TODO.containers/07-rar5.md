# 07 — RAR5

- **Priority:** P1
- **Depends on:** [01](01-archive-core.md), `omnizip-lzma`, [05](05-zip-encryption.md)
- **Estimated effort:** 2–3 weeks
- **Crate:** `omnizip-rar` (`rar5` module)

## Goal

RAR5 read/write: VINT varint headers, STORE + LZMA methods, multi-volume
(part/volume/numeric naming), solid archives, AES-256 (PBKDF2-HMAC-SHA256,
BLAKE2sp checksums), optional fields (mtime CRC32, recovery hooks → [13](13-par2.md)).

Carries the conformance rules learned in 0.16.89: dictionary-carrying
control bytes, props after dict resets — the Ruby encoder already encodes
them; the port must not regress them.

## Acceptance

- [x] Round-trips the Ruby RAR5 fixtures; `unrar t/x` byte-exact on our output
      (0.20.0: STORE method; `unrar` + `7zz` both accept our writer's output,
      extraction byte-exact — the Ruby writer itself is not unrar-compatible,
      it stores the method in the version bits)
- [ ] Multi-volume sets (3 naming patterns) + solid + encrypted round-trip
      (out of scope for 0.20.0: LZ/volumes/AES surface as clear
      `UnsupportedFeature`; the Ruby reference shells out to `unrar` for these)
- [ ] Multi-volume sets (3 naming patterns) + solid + encrypted round-trip
- [ ] BLAKE2sp checksums always present (spec); CRC32 auto-disabled under
      compression (the 0.4.0 lesson, encoded in tests)
